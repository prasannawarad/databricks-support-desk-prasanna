# Reflection

Honestly, the code was the easy part — the routes and templates came together fast. What actually slowed me down was permissions: a Databricks App runs as its own service principal that inherits nothing, so I had to work through `databricks_auth` roles, table grants, and sequence grants before a single insert would go through, and I hit a couple of `permission denied` errors that had nothing to do with my code before I figured that out. It didn't help that `PGUSER` means something different locally (my own identity) versus deployed (the service principal), so a setup that worked fine on my laptop still needed a second look before it worked in the app. Compared to just landing this in a Delta table, Lakebase actually enforces the relationship between a ticket and its messages — real foreign keys and a cascading delete — instead of me having to hope nothing ends up orphaned, which feels like the right tradeoff for something an app writes to constantly rather than something a warehouse just scans. If I kept building this, the next thing I'd add is a lightweight AI step that reads a new ticket and suggests a priority and category, since the message thread is already structured conversation history that's basically ready-made context for an agent.
